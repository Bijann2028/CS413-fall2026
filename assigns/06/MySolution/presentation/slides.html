04 · Evaluation strategy

Weak, left-to-right call-by-value.

(λx. body) value  →  body[x := value]

Target value = lambda abstraction

Application order

1. Evaluate the function.
2. Evaluate the argument.
3. Substitute and count one beta step.

Weak evaluation

Stop at a lambda value.
Do not reduce under its binder.
Do not perform eta reduction.

Explicit continuation stack; no separate source interpreter05 / 19

06 · Lexical scope

Fresh names prevent accidental capture.

Substitution hazard

(λy. x)[x := y]

Wrong:   λy. y
Correct: λy_1. y

Per-call naming supply

Reserve all source names.
Reserve names in translated terms.
Choose the first unused suffix.

Deterministic; no global counters.

FV(C[e]) = FV(e)

Let binds only its body. If fix binders coincide, the parameter shadows the function name.

07 · Compositional translation

Translate each constructor locally.

C[x]                = x
C[λx. e]            = λx. C[e]
C[e1 e2]            = C[e1] C[e2]
C[let x = e1 in e2] = (λx. C[e2]) C[e1]

Let's argument position preserves strict initializer evaluation.
Its lambda binds only the body.

Every child is checked, including unused branches and unapplied bodies.
Compiling LOOP returns syntax without executing it.

D0ExpVisitor dispatch; input AST remains unchanged08 / 19
08 · Control flow

Delay both branches. Force the selected one.

C[if c then t else f] =
  (C[c] (λu. C[t]) (λv. C[f])) I

Why thunks?

Branch lambdas are already values.
The Church boolean selects one.
Applying I forces that thunk.

Same rule for and / or

false and LOOP → false
true or LOOP → true

Ordinary target application stays strict.

u and v are fresh, unused parameters09 / 19
09 · Arithmetic

Predecessor carries a two-number state.

(0, 0)
→
(0, 1)
→
(1, 2)
→
(2, 3)

State transition

(previous, current)
   → (current, current + 1)

After n steps: (max(n − 1, 0), n).

Derived operations

Predecessor: first projection.
Subtraction: repeat predecessor.
Addition / multiplication: iteration.

The pair, successor, iteration, and projection all execute as pure beta reductions.

Predecessor(0) = 0; subtraction truncates at zero10 / 19

11 · Recursion

Z delays recursive self-application.

Z = λg. (λx. g (λv. x x v))
        (λx. g (λv. x x v))

C[fix f(x). e] = Z (λf. λx. C[e])

The extra λv makes the recursive argument a value.
Recursion unfolds when the function is called.

Ordinary Y unfolds eagerly under call-by-value.
A recursive function itself completes as a lambda before application.

17 · Correctness and limitations

Semantic evidence with explicit limits.

For closed, well-typed programs returning naturals, booleans,
or finite data pairs, the compiled observation agrees
with the source result, given sufficient resources.

Why the claim is plausible

Local translation rules, capture avoidance,
strict application, selected thunks,
and delayed recursive calls.

What remains outside the claim

Finite tests are not a proof.
Substitution can grow terms.
Observers are not universal validators.
Budget exhaustion does not prove divergence.

No parser, static type checker, or web interface is required18 / 19
